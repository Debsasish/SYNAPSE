More tools should not make an agent worse.

SYNAPSE keeps the model-facing tool surface constant while the capability catalogue scales. Instead of injecting every tool into prompt context, it resolves a compact activation set from a signed capability graph and exposes only six fixed meta-verbs.

Benchmark results

A cleaner information hierarchy for the scaling story

The main claim is simple: a flat protocol pays for the entire tool catalogue on every turn, while SYNAPSE pays for a bounded interface. The result is dramatic at large scale, but the site also preserves the uncomfortable parts of the story rather than hiding them.

What scales

SYNAPSE keeps the prompt interface fixed through six meta-verbs and an out-of-context resolver.

What is measured

Context tokens, cost, hit@k, reliability, ablations, and activation-size sweeps are all generated from the artifact.

What is not claimed

The catalogue is synthetic, the reference ANN path is not wall-clock optimal, and a live agent loop is not evaluated here.

Protocol explanation

Three planes, one bounded interface

SYNAPSE separates storage, resolution, and interaction. The model never receives the whole catalogue. It receives a small interface and asks for structure only when it needs it.

01

Capability knowledge graph

Capabilities, types, providers, and concepts live in a signed graph outside prompt context, enabling typed expansion and integrity checks without linear token growth.

02

Hybrid resolver

The resolver blends semantic, lexical, ontology-tag, graph-proximity, and type-fit signals to return a small shortlist and a calibrated confidence estimate.

03

Six fixed meta-verbs

The model-facing surface stays constant: intend, focus, plan, invoke, observe, and feedback.

Why T matters

Flat protocols spend tokens on every tool on every turn. SYNAPSE spends tokens on only the activated capability set.

Where decay remains

The remaining performance drop is mainly in tag-withheld cases rather than universal degradation as the catalogue grows.

Why this is reproducible

The repo includes figures, CSV outputs, a paper build, and tests, with a single-command reproduction path.

Why the reranker loses here

Jev often selects a textual look-alike because it only sees summaries, tags, and type strings, while the resolver also benefits from graph structure and type-fit signals. That is the right reading of the result here; it should not be generalized into a broad claim that Jev is worse in every setting.

Why lexical32 collapses at T = 1000

The main issue is shortlist recall. The gold capability appears in the lexical top-32 only 23% of the time, so Jev cannot recover once the correct option is absent. When the gold is present, lexical32 reaches 0.429 conditional hit@1.

Methodology and reproducibility

What to trust, what to caveat, and how to reproduce it

This site intentionally keeps the caveats close to the results. The artifact is reproducible, but the experiments still make bounded claims, especially for the new Jev baseline.

Core limitations

  • Synthetic catalogue rather than a production tool ecosystem.
  • Reference ANN path has wall-clock growth; the paper's claim is about prompt context, not this brute-force implementation's runtime.
  • Single benchmark framing with 90 real tasks and 5 impossible tasks.
  • Tag-withheld tasks remain the main source of SYNAPSE degradation.

Jev experiment caveats

  • One seed, two catalogue sizes, one prompt wording, and a synthetic catalogue.
  • The Jev-only full-catalog tournament was not completed because of upstream HTTP 429 rate limits.
  • PYTHONHASHSEED tie sensitivity changes resolver outputs by roughly ±1 percentage point; the Jev exporter pins seed 0, but run_all.py currently does not.
  • Jev is not bit-deterministic, model alias/version is not pinned, and responses are cached and de-duplicated.
